# EmbeddingGemma 2 실습 결과 (9단계 사람 동작 인식) — 성찬

## 요약

- **문제**: 웹캠에서 관절 17개(YOLO11n-pose)를 찾아 만세, 한팔들기, 손 흔들기, 악수를 규칙으로 판정할 때, 한 프레임만 보고 판정하면 어떻게 틀리는지 확인한다.
- **접근**: 실습 문서의 `pose_app.py`를 그대로 썼다. 같은 동작 순서를 두 번 했다.
  - 9-1 `--raw`: 프레임마다 판정
  - 9-2 기본 모드: 최근 0.6초 판정 중 60% 이상인 라벨만 확정하고, 손 흔들기는 1.5초 동안 손목의 좌우 움직임으로 따로 판정
- **결과**
  - raw는 라벨이 깜빡일 때마다 새 동작으로 세서, 실제 3회 안팎인 동작이 17~48회로 부풀었다. 손 흔들기는 한 번도 잡히지 않았다.
  - smooth는 횟수가 1/3~1/4로 줄었고, 손 흔들기가 처음 따로 잡혔다(5회).
  - 그래도 smooth도 실제의 2~4배를 셌다. 손을 흔드는 동안 반대 손도 올라가 한팔들기 ↔ 손 흔들기 ↔ 만세를 1~2초 간격으로 오갔다.

측정 조건: Jetson Orin Nano Super 8GB(공용), JetPack 7.2.1, MAXN_SUPER, ultralytics 8.4.184, yolo11n-pose, Logitech C920 1280x720. 2026-10-23 14:02~14:07 KST, 강의실 실내 조명, 카메라 정면 약 2~3m. 9-1은 13.8 fps, 9-2는 12.9~13.9 fps. 화면에 사람이 2명 잡혔고 동작은 주로 1명이 했다. 실제 횟수는 동작한 사람의 기억 기준이다.

## 결과 비교 (실습 문서 9-4 표)

| 동작 (실제 횟수) | 9-1 raw 카운트 | 9-2 smooth 카운트 | 비고 |
| --- | --- | --- | --- |
| 만세 (약 3회) | 17 | 7 | smooth에서도 손 흔들 때 만세로 튐 |
| 한팔들기 (약 3회) | 48 | 11 | 손 흔들기·만세와 오감 |
| 손 흔들기 (약 3회) | 0 | 5 | raw는 한팔들기로만 잡힘 |
| 악수 (9-2에서는 안 함) | 38 | 0 | raw는 8초 동안 32번 켜졌다 꺼짐. 9-1 때 실제 악수였는지는 확인 못 함 |
| 측면에서 만세 | 기록 없음 | 기록 없음 | 따로 세지 않음 |

## 해석

1. **raw의 횟수는 "동작 수"가 아니라 "깜빡임 수"다.** 관절이 조금만 흔들려도 라벨이 바뀌고, 바뀔 때마다 새 이벤트가 된다.
2. **한 프레임으로는 손 흔들기를 알 수 없다.** 흔드는 손과 든 손은 한 장면에서 똑같이 생겼다. 시간 창(1.5초)을 보고서야 구분됐다.
3. **시간 안정화는 깜빡임을 줄이지만 동작이 섞이는 문제는 못 푼다.** 손을 흔들 때 반대 손이 어깨 높이를 넘나들면 규칙상 만세와 한팔들기가 번갈아 성립한다. 규칙의 임계값(어깨 너비의 0.3배)을 사람이 정했기 때문이며, 실습 문서는 이 경계를 데이터에서 배우는 9-6(GRU)을 다음 단계로 둔다.
4. 화면에 다른 사람이 함께 잡히면 횟수가 섞인다. 측정할 때는 동작하는 사람만 화면에 둬야 한다.

## 9-3 녹화 + 9-6 학습 모델 (1차)

한 사람이 한 자리에서 동작마다 30~40초씩 녹화했다(사진 없이 관절 좌표만). 동작이 바뀌는 앞뒤 2초와 다른 사람의 기록은 지웠고, idle은 다른 동작보다 3~4배 길어서 가운데 600줄만 썼다.

| 라벨 | 줄 수 | 학습/검증 윈도 |
| --- | --- | --- |
| idle | 600 (원본 1,599) | 91 / 19 |
| wave | 568 | 85 / 17 |
| clap | 442 | 65 / 12 |
| arms_crossed | 412 | 60 / 11 |

`train_pose.py --task action --window 30`: GPU로 9초, 40 epoch, loss 1.241 → 0.008, **검증 정확도 1.000** (59개 전부 정답).

같은 사람이 바로 이어서 실시간으로 시험한 결과(14:18~14:19 KST, 약 1분, 15.5 fps):

| 비교 항목 | 규칙 (9-2) | 학습 모델 (9-6, 1차) |
| --- | --- | --- |
| 손 흔들기 | 5회 잡힘 | 2회 |
| 박수 | 판정 불가 (규칙 없음) | **0회** |
| 팔짱 | 판정 불가 (규칙 없음) | **16회, 다른 동작도 대부분 팔짱으로 판정** |
| 검증 점수 | - | 1.000 |

**가장 의외였던 발견: 검증 100%인 모델이 실제로는 거의 모든 자세를 "팔짱"이라고 했다.**

- 검증 데이터는 같은 녹화의 뒷부분 20%다. 같은 사람, 같은 자리, 같은 조명, 몇 초 뒤의 같은 동작이라 모델은 "그 녹화"를 외우기만 해도 만점을 받는다. 실습 문서도 "스크립트의 검증은 점수가 높게 나온다"고 경고한다.
- 라벨마다 윈도가 60~90개뿐이고 한 각도·한 거리뿐이라, 조금만 달라져도 팔이 몸 앞에 있는 자세(팔짱)로 몰렸다(추정).
- 사람이 잠깐 가려질 때마다 추적 ID가 바뀌어(#3 → #6 → #8) 30프레임 윈도가 끊긴 것도 판정을 줄였다.
- 실습 문서의 권장은 라벨당 여러 사람·여러 각도·거리다. 다음 개선은 모델이 아니라 데이터다: 다른 사람(민서), 다른 거리(1.5m·3m), 비스듬한 각도로 한 번 더 녹화하고, 학습에 참여하지 않은 사람으로 시험한다.

## 재현

```bash
cd lab && source ~/eg2/bin/activate
python pose_app.py --raw     # 9-1, http://<Jetson IP>:8200 (제목에 [raw])
python pose_app.py           # 9-2 (제목에 [smooth])
python pose_app.py --record data/action/wave.csv            # 9-3 녹화 (라벨 = 파일 이름)
python train_pose.py --data data/action --task action --window 30 --out models/action.pt
python pose_app.py --model models/action.pt                 # 9-6
```

사람 이미지는 저장하지 않는다. 기록은 동작 이벤트(JSON)와 정규화된 관절 좌표(CSV)뿐이다.
