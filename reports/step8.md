# EmbeddingGemma 2 실습 결과 (8단계 웹캠 물체 검색) — 성찬

## 요약

- **문제**: 웹캠으로 강의실 물체를 잘라 EmbeddingGemma 2로 색인하고 글자로 검색할 때, 검출기가 모르는 물체(라벨 목록 밖)를 어떻게 처리하는지 확인한다.
- **접근**: 실습 문서의 `app.py` 하나로 모드 5개를 같은 물체(캔 2종, 투명 플라스틱 컵, 휴대폰, 의자, 모니터)에 차례로 돌렸다. 앞의 3개는 문서 그대로, 뒤의 2개는 우리가 고친 것이다.
- **결과**
  - 어떤 방식이든 **라벨 목록 밖의 물체는 목록 안에서 가장 비슷한 것으로 억지로 붙는다.** 은색 캔은 yolo·relabel에서 `컵`, 파란 슬림 캔은 yoloe에서 `cell phone`이 됐다.
  - 목록에 `drink can`을 넣어도, 얼굴 옆에 세워 든 슬림 캔은 YOLOE가 프레임마다 `cell phone 0.84`로 튀었다. 같은 캔의 **크롭 임베딩은 `캔 음료` 0.67~0.73으로 꾸준했다.** 흔들리는 건 검출기이고, 임베딩이 안정적인 신호다.
  - **yoloe + 임베딩 재라벨(`--mode yoloe --relabel`)이 가장 정확했다.** 캔 8개 모두 `캔 음료`(휴대폰 0개), 휴대폰 8개 모두 진짜 휴대폰, 컵은 `투명 플라스틱 컵`으로 더 구체적으로 붙었고, 보여 준 물체의 검색 1위가 전부 맞았다.
  - 비용은 모드끼리 거의 같다: 검출 약 12 fps, 크롭 1개 임베딩 약 0.75 s, 앱 하나가 RAM 약 3.5 GB.

측정 조건: Jetson Orin Nano Super 8GB(공용), JetPack 7.2.1 (L4T R39.2.1), MAXN_SUPER, `jetson_clocks` 미사용, torch 2.14.1+cu132, sentence-transformers 6.2.0, ultralytics 8.4.184, **bfloat16**, 임베딩 512차원. Logitech C920, MJPG 1280x720. 2026-10-23 11:00~12:10 KST, 강의실 실내 조명, 같은 자리에서 손으로 들고 5초 이상. RAM은 보드 전체 값이라 같은 보드의 시계열 서비스 컨테이너(약 2 GB)가 포함된다.

## 해석

1. **검색과 라벨은 다른 길이다.** relabel에서 "캔 음료"를 검색하면 캔 사진이 1위로 나오지만 카드의 라벨은 `컵`이다. 검색은 이미지 임베딩끼리 비교하고, 라벨은 정해진 목록에서 고르기 때문이다.
2. **닫힌 목록은 모르는 물체를 틀리게 부른다.** COCO 80종(yolo), 문서의 17개(relabel·yoloe) 모두 "모르겠다"는 답이 없다. `LABEL_MIN` 0.20은 거의 모든 크롭이 통과해서 거르는 역할을 못 했다(우리 크롭의 최고 점수는 0.60~0.73).
3. **목록만 고쳐서는 부족했다.** `drink can`을 넣자 은색 캔은 맞았지만, 얼굴 옆에 세워 든 슬림 캔은 검출기가 "얼굴 옆, 손에 쥔 길쭉한 물체"라는 맥락 때문에 휴대폰으로 골랐다(추정).
4. **검출기가 박스, 임베딩이 이름을 맡을 때 가장 좋았다.** 실습 문서의 확장 과제("yoloe 박스에 relabel을 함께 적용")를 `--relabel` 옵션으로 넣었다. 검출기가 cell phone이라 해도 크롭이 `캔 음료`에 더 가까우면 이름을 바꾼다. 같은 추적 ID는 30초에 한 번만 다시 비교해서, 처음 몇 초는 검출기 라벨이 보인다.
5. **강의실 서비스에는 5번(yoloe + relabel)을 쓰겠다.** 속도·메모리 비용이 다른 모드와 같고, 라벨 목록에 실제 물체 이름을 넣는 것만으로 정확도가 올라간다. 다만 RAM 3.5 GB를 써서 공용 보드에서는 다른 모델과 동시에 띄울 수 없다.

## 실패 → 원인 → 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 기본 포트 8000에서 실행 불가 | 보드의 8000·8086·8090·8091·8100·8130을 다른 서비스가 사용 | `--port` 기본값을 8200으로 |
| 모드를 바꾸자 "웹캠을 열 수 없음" | `kill`(SIGTERM)을 받은 앱이 웹캠을 잡은 채 멈춤 | `kill -9`로 종료 |
| 브라우저 영상만 검게 멈춤(카드는 갱신) | Mac↔Jetson이 Tailscale 중계(DERP)로 연결돼 MJPEG 스트림이 끊김. 보드 안에서 받은 프레임은 정상 | 새로고침, 같은 와이파이로 직접 연결 |
| yoloe 첫 실행이 2분 걸림 | ultralytics가 clip·ftfy를 자동 설치하고 `mobileclip_blt.ts`(572 MB)를 받음 | 한 번만 발생 |
| 로그 파일이 계속 커짐 | ultralytics가 `half` 인자 경고를 매 프레임 남김 | 오래 띄울 땐 로그를 `/dev/null`로 |

## 재현

```bash
cd lab && source ~/eg2/bin/activate
pip install -c ~/eg2/torch-pin.txt ultralytics fastapi "uvicorn[standard]"
free -h                                   # available 3 GB 이상일 때만
python app.py --mode yolo                 # 1 기준선
python app.py --mode relabel              # 2 개선 1
python app.py --mode yoloe                # 3·4 개선 2 (LABELS 수정 전·후)
python app.py --mode yoloe --relabel      # 5 확장: 검출은 YOLOE, 이름은 임베딩
# 브라우저: http://<Jetson IP>:8200
```

크롭은 `crops/<모드>/`에 따로 쌓인다(사람은 저장하지 않음).
