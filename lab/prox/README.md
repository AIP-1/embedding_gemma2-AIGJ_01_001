# 10단계: 카메라 2대로 물체 접근 감지

가이드 10단계 코드를 그대로 옮기고 아래만 바꿨다.

- 포트 8000 → 8200 (보드에서 8000은 다른 서비스가 쓴다)
- 카메라를 보드 두 대에 하나씩 꽂는 구성을 지원한다. 가이드는 두 카메라를 한 보드에 꽂는다.
  - `cam_server.py`: 카메라가 꽂힌 다른 보드(2호기)에서 MJPEG로 내보낸다 (포트 8210, opencv만 필요)
  - `--cams` 에 장치 번호 대신 `http://<보드>:8210/stream` 을 쓸 수 있다 (`stereo.open_source`)
  - `proximity_app.py --lag-ms 0 <ms>`: 원격 스트림의 전송 지연만큼 받은 시각을 앞당긴다
  - `calib_extrinsics.py --intr A B`: 렌즈 보정 파일을 직접 지정한다 (원격 카메라는 장치 번호가 없어서)
- `checkerboard_9x6.png`: 인쇄 대신 태블릿·노트북 화면에 띄우는 체커보드 (내부 코너 9x6)

## 구성

| 보드 | 카메라 | 실행 |
| --- | --- | --- |
| 1호기 | cam0 (C920, /dev/video0) | `calib_intrinsics.py`, `calib_extrinsics.py`, `proximity_app.py` (YOLO는 여기서만) |
| 2호기 | cam1 | `calib_intrinsics.py`(1회), `cam_server.py` |

시간 차: 앱은 프레임을 **받은 시각**으로 두 카메라를 맞춘다. 그래서 두 보드의 시계는 상관없고,
2호기 프레임은 네트워크 지연만큼 늦게 도착한다. `ping` 왕복 시간의 절반을 `--lag-ms`로 준다.
걸음(1m/s) 기준 지연 50ms를 보정하지 않으면 위치가 약 5cm 어긋난다.

## 화면 체커보드

`checkerboard_9x6.png`를 태블릿·노트북에서 전체 화면, 확대 없이 띄운다. 칸 한 변을 자로 재서
`--square`에 m 단위로 준다 (예: 2.1cm → `--square 0.021`). 화면 반사가 심하면 밝기를 낮추고 비스듬히 비춘다.
